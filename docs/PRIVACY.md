# 개인정보 처리방침 (초안)

> **이 문서는 초안이다. 법률 문서가 아니고, 법률 검토를 거치지 않았다.** 가계부 앱이 무엇을 어디에 두는지를 설계서(`docs/SPEC.md`)에 적힌 대로 풀어 쓴 것이다. 설계서에 "예정"으로 적힌 기능도 함께 적었으므로, 지금 배포된 앱에는 아직 없는 것이 있을 수 있다. 설계가 바뀌면 이 문서도 고친다. 여러 사람이 쓰는 서비스로 운영하기 전에 법이 요구하는 항목을 갖췄는지 따로 검토해야 한다.

## 한눈에

- 붙여넣은 문자 · 문장과 이미지(원문)는 기기 안에서만 해석한다. 서버로 보내지 않고, 기기에도 남기지 않는다.
- 서버에 올라가는 것은 사용자가 확인해 저장한 거래와 설정, 그리고 로그인에 쓰는 이메일 주소다.
- 서버는 Supabase(서울 리전)에 있다.
- 앱에서 계정을 삭제하면 서버의 가계부와 계정이 지워진다.

## 무엇을 어디에 두는가

### 기기에 두는 것

| 무엇 | 어디에 | 비고 |
| --- | --- | --- |
| 가계부(거래, 자산, 분류, 예산, 반복 거래, 분류 규칙, 월별 요약, 프로필) | 기기의 로컬 DB. Windows · Android는 앱 폴더의 파일, 웹은 브라우저 저장소 | 모든 읽기와 쓰기가 여기에서 먼저 일어난다 |
| 서버에 올릴 변경의 대기열, 동기화 상태, 동기화 충돌 기록 | 기기의 로컬 DB | 서버에 올라가지 않는다. 충돌 기록은 30일이 지나거나 200건을 넘으면 오래된 것부터 지운다 |
| 작업 기록(언제 · 어떤 경로로 · 몇 건을 저장했는지) | 기기의 로컬 DB | 기기마다 따로다. 원문은 남기지 않는다 |
| 기기 설정(테마, 잠금 번호의 해시, 첫 실행 안내를 봤는지 등) | 기기의 설정 저장소 | 잠금 번호는 솔트를 섞은 해시로만 두고 서버로 보내지 않는다 |
| 내려받은 AI 모델 파일(Windows · Android) | 기기 | |
| 로그인 세션 | Android는 OS의 보안 저장소, Windows는 앱 폴더의 파일, 웹은 브라우저 저장소 | |

- 기기의 DB 파일은 암호화하지 않는다. 앱 잠금은 화면을 가릴 뿐이다.
- 웹에서는 브라우저가 저장소를 지울 수 있다(예: Safari는 7일 동안 열지 않은 사이트). 로그인해 있으면 서버에서 다시 받는다.
- 내보내기로 만든 파일(CSV · Excel)은 사용자가 고른 곳에 저장된다. 그 뒤의 보관은 사용자의 몫이다.

### 서버에 두는 것

| 무엇 | 비고 |
| --- | --- |
| 계정: 로그인에 쓰는 이메일 주소와 인증 정보 | Supabase Auth가 맡는다. Google로 로그인하면 Google의 로그인 화면을 거친다 |
| 사용자가 확인해 저장한 거래: 날짜, 시각, 금액, 자산, 상대방, 분류, 메모, 태그 등 | 검토함에서 승인했거나 직접 입력해 저장한 것만 올라간다 |
| 설정: 자산, 분류, 예산, 반복 거래, 분류 규칙, 월별 요약, 프로필(표시 이름, 월 시작일) | |
| 동기화 기록: 기기(설치)를 구분하는 무작위 식별자와 올린 묶음의 처리 결과 | 같은 묶음을 두 번 적용하지 않으려고 90일 보관한다 |

- 서버의 모든 표에 행 단위 보안을 걸어, 로그인한 사용자는 자기 가계부의 행만 읽을 수 있다.
- 지운 행은 삭제 표시가 붙은 채 남는다(다른 기기에 삭제를 알리기 위해서다). 서버에서는 90일이 지난 삭제 표시와 동기화 기록을 주마다 도는 정리 작업이 실제로 지운다. 이 작업은 운영자가 켜 두어야 돈다.
- 운영자가 서버 백업을 켜 두었으면, 서버 DB를 매일 덤프해 암호화한 파일을 GitHub(저장소의 Actions 산출물)에 30일 보관한다. 이 백업에는 가계부의 행이 들어 있고 계정 정보(이메일, 인증 정보)는 들어 있지 않다. 계정을 삭제한 뒤에도 그 전에 만들어진 백업에는 보관 기간이 끝날 때까지 가계부의 행이 남는다.

### 저장하지 않는 것

- **붙여넣은 글과 이미지(원문).** 기기 안의 규칙과 모델이 읽어 거래 초안을 만들고, 원문은 서버에도 기기의 저장소에도 남기지 않는다. 이미지는 메모리에서만 다룬다.
- 저장되는 것은 사용자가 초안을 확인해 저장한 거래다. 원문에서 읽어 낸 값(금액, 날짜, 상대방 이름 등)은 그 거래의 항목으로 저장된다.

예외가 하나 있다. Windows 앱의 설정에 사용자가 직접 띄운 모델 서버의 주소를 적으면, 앱은 해석할 글을 그 주소로 보낸다. 사용자가 적지 않으면 일어나지 않는다.

## 서버의 위치

서버는 Supabase(PostgreSQL, 인증)이고 리전은 서울이다. 서버는 인증 · 저장 · 동기화만 맡고, 입력을 해석하지 않는다.

## 기기가 밖과 주고받는 것

| 연결 | 대상 | 보내는 내용 |
| --- | --- | --- |
| 로그인 | Supabase Auth, Google 로그인 화면 | 계정 인증 정보 |
| 동기화 | Supabase(서울) | 확인해 저장한 거래와 설정 |
| 웹 앱 불러오기 | GitHub Pages | 없음 |
| 모델 내려받기(Windows · Android) | Hugging Face | 없음 |
| 모델 카탈로그, 버전 확인, 설치 파일 | GitHub 공개 저장소의 파일과 Releases | 없음 |

- "없음"은 앱이 사용자의 데이터를 실어 보내지 않는다는 뜻이다. 어느 연결이든 상대 서버는 접속한 기기의 IP 주소 같은 접속 정보를 볼 수 있다.
- 글꼴과 아이콘은 앱에 들어 있어, 외부 글꼴 서버에 접속하지 않는다.

## 지우는 방법

- **계정 삭제**: 앱의 설정 → 계정 → "계정 삭제". 서버에서 그 계정의 가계부와 딸린 모든 행, 인증 계정이 지워진다. 기기에서는 가계부 · 대기열 · 작업 기록을 지우고 로그아웃한다. 아직 서버에 올리지 못한 변경은 버린다.
- **로그아웃**: 그 기기에서만 로그아웃한다. 기기의 가계부는 지우지 않는다.
- **거래를 지우면** 삭제 표시가 붙어 화면에서 사라진다. 서버의 삭제 표시는 90일 뒤 정리 작업이 실제로 지운다(위 "서버에 두는 것").
- 서버 백업에 남은 행은 보관 기간(30일)이 지나면 사라진다.
