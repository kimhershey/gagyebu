# eval/

규칙과 모델을 고르고 회귀 검사하는 데 쓰는 표본과, 그것으로 잰 기록이다.

```
golden/paste.jsonl              결제 문자 · 입출금 알림 · 안내문 49건 (규칙을 다듬는 데 쓴다)
golden/sentences.jsonl          한 줄 문장 40건 (규칙을 다듬는 데 쓴다)
golden/holdout_paste.jsonl      처음 보는 형식의 문자 20건 · 안내문 6건 (다듬는 데 쓰지 않는다)
golden/holdout_sentences.jsonl  처음 보는 문장 20건 (다듬는 데 쓰지 않는다)
tool/build_*.py                 위 파일을 만드는 스크립트. 표본은 여기에 적는다
reports/                        잰 결과(JSON). 틀린 표본의 목록이 들어 있다
```

## 표본의 꼴

`paste.jsonl` · `holdout_paste.jsonl`의 한 줄:

| 키 | 뜻 |
| --- | --- |
| `id` | 표본 이름 |
| `channel` | `sms`(문자) · `push`(앱 알림의 제목과 본문) · `notice`(기록하면 안 되는 안내문) |
| `today` | 연도 없는 날짜를 풀 때의 기준일 |
| `text` | 원문. 이름과 계좌 · 카드 번호는 가린 값이다 |
| `kind` | `transaction` · `non_transaction` · `unrecognized` |
| `expect` | `transaction`일 때의 정답 필드 |
| `synthetic` | 공개 표본이 아니라 형식에 맞춰 만든 표본이면 true |

`sentences.jsonl` · `holdout_sentences.jsonl`은 `text`, `today`, `expect`(날짜 · 금액 · 방향)와 `counterparty_contains`(상대나 내용에 들어 있어야 하는 말)를 가진다.

## 두 가지 표본

- **다듬는 표본**(`paste` · `sentences`)은 공개 저장소의 테스트 데이터와 금융사 공식 안내에서 모은 형식이다. 규칙과 프롬프트를 이 표본으로 고쳤으므로 여기서의 일치율은 일반화 성능이 아니라 회귀 검사다.
- **홀드아웃**(`holdout_*`)은 규칙을 다 고친 뒤에 지어낸 표본이다. 가상의 금융사와 다른 필드 순서, 다른 말투를 썼다. 여기서 틀린 것을 보고 규칙을 고치면 안 된다. 같은 종류의 다른 표본을 다듬는 표본에 더하고 그것으로 고친다. 그래야 홀드아웃의 점수가 처음 보는 글에 대한 점수로 남는다.

홀드아웃도 같은 사람이 지은 46건이라 실제 문자보다 쉽다. 표본이 20건이면 한 건이 5%p다. 아래 수치는 방향을 정하는 데 쓰고, 출시 기준은 실제 문자를 모아 다시 잰다.

## 재는 법

```bash
cd app

# 규칙만 (모델 없음)
dart run tool/llm_eval.dart --mode=rules --set=holdout

# 모델만: 형식 규칙을 끄고, 후보 추출 규칙과 모델로만 읽는다
llama-server -m Qwen3.5-2B-Q4_K_M.gguf --host 127.0.0.1 --port 8088 -c 4096 -t 4 --reasoning-budget 0
dart run tool/llm_eval.dart --endpoint=http://127.0.0.1:8088 --name=qwen3.5-2b-q4_k_m --set=all

# 앱과 같은 순서: 규칙 먼저, 규칙이 못 읽은 것만 모델
dart run tool/llm_eval.dart --endpoint=… --name=… --mode=app --set=holdout --out=../eval/reports/x.json
```

앱의 `test/ai/paste_golden_test.dart`와 `quick_entry_golden_test.dart`는 다듬는 표본으로 규칙을 검사한다(CI에서 돈다). 모델을 쓰는 평가는 CI에 넣지 않았다.

## 2026-11-17 실측

- 기계: x86-64 4코어 CPU, GPU 없음, RAM 15GB. llama.cpp(커밋 d3c3e24) `llama-server`, 스레드 4, 문맥 4096.
- 모델: [Qwen3.5-2B](https://huggingface.co/Qwen/Qwen3.5-2B) Q4_K_M 1.28GB, [Qwen3-4B-Instruct-2507](https://huggingface.co/Qwen/Qwen3-4B-Instruct-2507) Q4_K_M 2.50GB. 둘 다 Apache-2.0.
- 2B의 생성 속도는 초당 약 13토큰이었다. 휴대폰에서는 재지 않았다.

### 처음 보는 표본(홀드아웃)

모르는 형식의 문자 20건과 안내문 6건. 프롬프트 v4로 한 번만 돌린 값이다. 모델 열은 형식 규칙을 끄고 잰 것이고, 2B는 앱과 같은 순서로 돌려도 같은 값이 나왔다(이 표본에는 형식 규칙이 아는 문자가 없다).

"규칙만"의 문장 쪽 `상대 · 내용` 19/20은 후하게 나온 값이다. 규칙은 날짜와 금액을 뗀 나머지를 통째로 상대에 넣기 때문에 찾는 말이 들어 있기만 하면 맞은 것으로 센다.

### 여기서 정한 것

1. **모르는 형식의 문자는 모델에 넘긴다.** 규칙만으로는 상대방을 한 건도 가려내지 못했고(나머지 글을 통째로 넣는다), 모델을 붙이면 20건 중 15건이 맞았다. 모든 항목이 맞은 초안은 0건에서 13건이 됐다.
2. **사람이 쓴 한 줄 문장은 규칙으로 읽는다.** 금액 · 날짜 · 방향이 규칙 17/20, 모델 15/20이었고 규칙은 기다림이 없다. 모델이 규칙의 실수를 고친 문장은 없었다. 앱의 순서(`lib/ai/input_interpreter.dart`)를 이렇게 바꿨다: 금융사가 보낸 글로 보이지 않는 한 줄은 규칙이 먼저 읽고, 규칙이 금액을 찾지 못할 때만 모델에 넘긴다.
3. **텍스트 해석에는 2B면 된다.** 4B는 정확도가 같았고(모든 항목 13/20 대 13/20) 시간은 2.5배였다. 날짜 · 금액 · 방향 · 이름을 규칙이 후보로 좁혀 주기 때문에 모델 크기의 차이가 드러날 자리가 적다. 4B는 월별 총평과 이미지 쪽에서 다시 견준다.
4. **설계안의 목표에는 아직 못 미친다.** 모르는 형식에서 모든 항목이 맞은 초안이 65%다. 검토 카드에서 사람이 확인해야 저장되는 구조라 쓸 수는 있지만, 자주 쓰는 형식은 규칙으로 옮겨야 한다.

2번의 순서를 바꾼 뒤(프롬프트 v5) 앱과 같은 순서로 홀드아웃을 다시 돌리면 문자는 모든 항목 14/20, 문장은 금액 · 날짜 · 방향 17/20이고 문장은 기다림 없이 끝난다(`reports/…_prompt-v5_holdout-app_after.json`). 이 값은 홀드아웃을 보고 정한 순서로 잰 것이라 처음 보는 표본에 대한 값이 아니다.

### 홀드아웃에서 틀린 것

다듬는 표본에 같은 종류를 더해 고칠 것들이다. 홀드아웃에 맞춰 고치지 않았다.

| 표본 | 무엇이 틀렸나 | 원인 |
| --- | --- | --- |
| `김민지님이 50,000원을 보냈어요` | 방향(받은 돈을 지출로) | '보냈'이라는 낱말로 방향을 못 박는 규칙. 누가 보냈는지를 보지 않는다 |
| `[쓱페이] 환불 완료 …`, `티머니 충전 …` | 방향 | 환불 · 충전의 방향을 모델에 맡겼다. 환불은 그 뒤에 '지출의 취소'로 고정했다(v5) |
| `[한빛증권] … 받는분:이민수` | 상대방(`CMA계좌`를 고름) | `받는분:` 같은 꼬리표를 떼지 못한다 |
| `우체국 … 한국전력공사`, `신협 …` | 상대방(금융사 이름을 고름) | 금융사 이름 목록에 없는 이름 |
| `배달의민족 … (교촌치킨 역삼점)` | 상대방 | 괄호 안의 가게 이름을 후보로 묶지 못한다 |
| `Approved KRW 32,000 at COUPANG …` | 거래로 읽지 못함(2B) | 영어 알림. 거래 낱말 규칙이 한글뿐이다 |
| `… 이체한도가 1일 5,000,000원으로 변경 …` | 안내문을 거래로 읽음 | '이체'와 금액이 있고 안내문 표지 목록에 '한도 변경'이 없다 |
| `… 병원비 45,000원 실비 청구 예정` | 거래로 읽지 못함 | '예정'을 안내문 표지로 본다 |
| `택시비 만 이천원 어젯밤`, `5일에 받은 …` | 날짜 | '어젯밤', '5일에'를 날짜로 읽지 못한다 |
| `부모님 용돈 드림 30만원` | 방향(모델) | '드림'이 나간 돈이라는 것을 놓쳤다 |

### 프롬프트를 고쳐 온 기록

다듬는 표본에서 형식 규칙을 끄고 2B 모델만으로 잰 값이다. 같은 표본으로 고쳤으므로 뒤로 갈수록 좋아지는 것은 당연하다. 무엇이 효과가 있었는지 보는 데 쓴다.

| 판 | 바꾼 것 | 문자: 금액 | 날짜 | 방향 | 상대방 | 안내문 | 문장: 금액 · 날짜 · 방향 모두 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| v1 | 달력 표를 주고 모델이 날짜를 고른다. 금액만 후보 | 30/39 | 10/39 | 24/39 | 17/39 | 6/9 | 32/40 |
| v2 | 날짜도 규칙이 후보로. 방향은 낱말로 정해지면 고정. 예시 5개 | 29/39 | 32/39 | 32/39 | 6/39 | 8/9 | 37/40 |
| v3 | 이름도 규칙이 후보로. 거래 여부(`real`)를 답의 끝에서 판정 | 32/39 | 32/39 | 32/39 | 28/39 | 9/9 | 40/40 |
| v4 | 거래 낱말과 금액이 있고 안내문 표지가 없으면 거래로 고정. 금액 후보가 없으면 비움 | 39/39 | 39/39 | 39/39 | 37/39 | 9/9 | 40/40 |
| v5 | 취소 · 환불은 방향을 묻지 않고 지출의 취소로 고정 | 39/39 | 39/39 | 39/39 | 38/39 | 9/9 | 40/40 |

같은 v4로 4B는 문자에서 금액 · 날짜 · 방향 39/39, 상대방 38/39, 안내문 8/9, 문장에서 39/40이었다(건당 약 12초).

배운 것:

- 소형 모델에 **계산이나 베껴 쓰기를 시키면 틀린다.** 달력 표에서 날짜를 고르게 했을 때 26%만 맞았다. 규칙이 풀어서 후보로 주자 82%가 됐다.
- **자유롭게 쓰게 하면 지어내거나 엉뚱한 것을 고른다.** 상대방을 글로 쓰게 했을 때 15%까지 떨어졌다(은행 이름, 명의자, null). 규칙이 남은 말을 후보로 주고 그 안에서만 고르게 하자 72%, 후보를 다듬자 95%가 됐다.
- **판정을 첫 토큰에 두면 섣불리 빠진다.** `{"tx":[]}`로 먼저 빠져나가던 것을, 거래를 먼저 적고 끝에서 `real`을 답하게 하자 문장의 "거래 없음" 오답이 없어졌다.
- 결국 모델에 남는 일은 **후보 가운데 무엇이 상대이고 무엇이 내용인지, 분류가 무엇인지, 돈이 움직인 글인지**다.

### 다음에 잴 것

- 답에서 후보가 하나뿐인 항목을 빼면 건당 20토큰쯤 준다(문법이 강제하는 토큰도 한 개씩 생성하느라 시간이 든다). 약 1.5초를 줄일 수 있다.
- 휴대폰에서의 속도와 메모리(llamadart 연동 뒤).
- 분류(`cat`) 정확도. 표본에 정답 분류가 아직 없다.
- 월별 총평의 품질(2B와 4B).
